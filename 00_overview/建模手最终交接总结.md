# 建模手最终交接总结

## 交给算法手

### 任务边界

- 任务不可抢占、不可拆分；实时任务到达即开工；任务不得占用 Hour 2406。
- Q1固定来源区域，弹性任务可延后；Q2/Q4按单向网络时延打开可行迁移区域。
- 能源动作覆盖 `0..2406`；`SOC_-1=InitialSOC`；终端约束 `SOC_2406>=InitialSOC`。
- Q3固定 `Baseline_AI_IT_Load_MW+NonAI_IT_Load_MW`，不读取 Q2 任务表。
- Q4任务变量独立，每次改变任务安排必须重新计算 AI IT、GPU、IT和设施负荷。

### 基准和初始化

- `x0`只用于附件负荷复现，不得作为可行四格基准；它有44个 GPU 超限小时。
- `x_base`已冻结在 `02_data/processed/x_base_task_schedule.csv`，50,000任务全部排程，90个弹性任务延后，任务层和算力层零违约。
- `M00_Q1`：第一问解释性状态，固定 `x_base`、无储能且禁止外送，绝不参与四格改善率；`M00_fair`：固定 `x_base`、无储能，但与其他四格使用同一外送政策。`M01-xbase`：固定 `x_base`、开放储能；`M10`：任务柔性、无储能；`M11`：任务和能源联合柔性。
- Q3的 `B3_ref` 独立报告，不直接标记为 `M01`。
- 除 `M00_Q1` 外，四格与 `Q3-B3ref` 固定 `ExportPolicy=PERMIT_RE_ONLY`，即只允许新能源外送、`GridSell=RenewableSell`、禁止购电转售，并共用附件的外送上限和售电价格；每次运行将该政策写入 `run_manifest`。

### 算法自由度

可以使用 MILP、CP-SAT、LNS、滚动优化或混合算法；可以采用聚合、候选点裁剪和窗口分解，但最终必须还原逐任务不可抢占表，并报告小样本最优 gap、上下界、运行时间和修复记录。

### 必须交回的结果

1. `task_schedule.csv`；
2. `energy_schedule.csv`；
3. `kpi_summary.csv`；
4. `solver_log.jsonl`。

所有结果必须通过任务唯一指派、实时即开、截止期、时延、GPU/IT/设施容量、能源分流、负荷平衡、SOC递推、购售电/充放电互斥和终端 SOC 验收。四格全部完成后才能计算 `S_K`。

## 交给论文手

### 论文主线

按“数据特征与预测检验 → Q1基础调度 → Q2算力柔性 → Q3储能柔性 → Q4联合优化 → 情景比较 → 局限”组织。核心叙事是：先保证任务可行性，再释放算力柔性和能源柔性，最后量化联合收益。

### 每问表达重点

- Q1：说明 GPU需求、GPU-hour和持续时间为什么必须分开统计；预测采用时间顺序留出，最后24小时调度使用实际任务。
- Q2：说明迁移/时移如何改变 AI 负荷时空分布；用硬约束 + ε-约束形成可解释折中解。
- Q3：说明固定负荷后储能收益可以单独归因；Q3和四格 `M01` 必须分开命名。
- Q4：说明任务变量直接进入能源平衡；不能把 Q2 任务解锁死后冒充联合优化。

### 论文中可使用的比较

季节性朴素法、FCFS/EDF、全量 MILP 小样本、简单加权多目标、先任务后储能、附件 `B_ref` 和 `M00/M01/M10/M11` 四格消融。每个优势都要绑定可测指标和验证方法。

### 目前禁止写入

Q1最终预测优劣、Q2-Q4成本/碳排/新能源改善率、Pareto前沿、`S_K`、推荐策略和全局最优性。算法结果未回传前统一使用 `[待算法填入]`，结论状态标为 `EXPECTED` 或 `BLOCKED`。
